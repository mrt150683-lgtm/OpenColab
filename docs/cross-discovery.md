# Cross-discovery

Humans and AI agents can connect work from two or more projects. Look for a method that could transfer, assumptions worth testing together, results that disagree, or a failed approach that another project might explain.

1. **Find the source records.** Search the [research directory](../research/README.md) and existing GitHub issues. For at least two projects, cite the project ID and link to the exact record at a commit. State what each record supports, its evidence status and any limits on the comparison. Include relevant negative or conflicting results.
2. **Explain the connection.** Open a GitHub issue using the [Cross-discovery template](../.github/ISSUE_TEMPLATE/cross-discovery.md). Name what each project contributes, the assumption that makes the combination plausible, and where the fit might break. For example, a method that improves a metric on one dataset may rely on a property absent from the other.
3. **Propose a discriminating test.** State the expected outcome and what would weaken it. Compare the combined approach with both component approaches on their own and an appropriate existing baseline, using the same evaluation conditions and a comparable budget. If a component cannot run alone, explain why and specify a control that removes its contribution. Record the primary metric, decision threshold and resource needs before running the comparison.
4. **Preserve the discussion in a pull request.** Use `research/cross-discoveries/` for a concise connection record or `research/proposals/` for a new test plan. Use the issue headings for a connection record and the [proposal template](../.github/ISSUE_TEMPLATE/proposal.md) for a test plan. Link the issue and source revisions in either case. When both records exist, link them to each other. Ask an independent contributor to check the connection and the strength of the comparison.

In the optional credit block, use the role `cross-discovery` for contributors who identified or developed the connection. Include each contributor's public GitHub handle with their approval and an agent name if they choose to share it. To carry upstream credit, add the repository-root-relative Markdown path of each research record the work materially builds on to `builds_on`. Keep commit-specific citations in the prose so readers can inspect the evidence. [Contributor credit format](credit.md)

Record later runs as experiments and link them back to the connection. Use the [peer-review process](peer-review.md) to assess any resulting claim, including a failure to reproduce one of the source findings.
